## 测试 5：否决后记忆 — ❌ 首轮失败；代码已修复，待正式复测

这是整个评测中**最有价值的一次失败**，暴露了两个真实缺陷。

### 测试过程

1. **第一步**：人工否决 CR-101，理由为——"疏散复核应由消防专业正式评估后决定，AI 不应反复把中庭人流规模当作重新打开疏散方案的理由。"
2. **第二步**：投入同类新材料"中庭活动预案更新"（峰值人数进一步上升，运营方再次希望关注疏散安排）。

### AI 的错误输出

影响路径：`新材料 → challenges → 工作假设/Assumption → HC-I001; HC-I002`

"该运营变化可能提示连续开放中庭的公共动线使用强度增加，但不构成对既有消防/疏散方案或中庭设计决定的直接修改依据。"

### 两个失败点

**失败点 1：类型混淆**
AI 把 **HC-I001（连续的公共动线）** 和 **HC-I002（灵活的大空间）** 标成了"工作假设/Assumption"并指向"受到挑战"。但这两个是**设计意图（Intent）**，不是工作假设（Assumption）。

- 意图 = 项目希望达成的目标，不应被"挑战"
- 假设 = 暂时使用的推理前提，才可能被新证据影响

**失败点 2：人工否决未被真正理解**
AI 表面记住了"别再提疏散方案"（确实没重复"疏散"结论），但没有理解否决背后的逻辑（"AI 不应反复拿人流规模当作重新打开判断的理由"）。结果它**换了个对象**——把影响指向了 HC-I001/HC-I002——而不是收敛。这说明它只记住了表层措辞，没有遵守人工判断的实质约束。

### 诊断与修复方向

1. 提示词需强化：**意图是目标，不应被新证据"挑战"；只有假设和决定才可能被影响。**
2. 人工否决的理由需要更结构化地注入下一轮语境，而不只是"别再说某句话"。
3. 需要在 system prompt 里明确各类型的语义边界（Source / Assumption / Intent / Decision 各自的角色）。

### 已实施修复

1. system prompt 明确约束 Source / Assumption / Intent / Decision 的语义与 ID 类型：Intent 是目标，不能被重新标成 Assumption。
2. 服务端校验每个关系字段的 ID 前缀；类型与字段不一致的路径不会进入结果。
3. 每轮分析都会注入人工判断的动作、候选路径、否决理由和修改内容。
4. 对 `reject` 增加约束：没有实质性新增独立证据时，同类触发不得重新提出已否决路径，也不得换一个 Intent 绕过否决。

### 修复后复测 5B — ⚠️ 部分通过

**输入**：运营方再次确认中庭将用于大型公共活动并希望重新关注疏散安排；材料明确没有新的消防评估、出口能力、人员密度或活动布置数据。

**通过项**：
- 没有重新提出已否决的 HC-A001 路径；
- 没有换一个 Intent 绕过人工否决；
- 没有再次混淆 Assumption 与 Intent；
- 明确要求出现独立且实质性的新专业证据后再判断。

**未通过项**：输出没有明确引用原来的人工否决编号或否决理由。因此无法区分“系统应用了历史人工判断”和“模型只是因为证据不足而没有建链”。

**判定**：部分通过，不能宣称否决记忆已经验证。系统已增加 `appliedPriorReviewId` 和人工决定影响说明字段；需要进行 5C 复测，只有输出明确显示采用了哪条历史人工决定，才可判定通过。

### 修复后复测 5C — ✅ 通过（轻微状态瑕疵已修复）

**输入**：与 5B 相同，再次确认中庭大型公共活动需求，但不提供新的消防评估、出口能力、人员密度或活动布置数据。

**结果**：
- ✅ 影响路径为空，没有重新提出 HC-A001、HC-I001 或 HC-D001。
- ✅ 明确引用人工决定 `CR-1788772880287`。
- ✅ 准确解释人工否决的约束：仅以活动人流规模重新打开疏散方案的理由不足；本次材料没有独立的新证据。
- ✅ 没有换成其他 Intent、Assumption 或 Decision 绕过人工否决。
- ✅ 说明只有出现独立且实质性的新专业证据时才重新复核。
- ⚠️ 输出正文写“仅作为监测事项”，但 level 字段仍显示“需要专业复核”。服务端已增加一致性规则：采用历史否决、且影响路径为空时，状态自动归为 `monitor`。

**判定**：测试 5 核心目标通过。系统能够明确证明采用了哪条历史人工决定，以及该决定如何改变本轮 AI 输出。状态显示问题属于结果归一化瑕疵，已经修复。
